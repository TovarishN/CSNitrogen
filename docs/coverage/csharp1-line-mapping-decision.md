# Approved: exact historical #line mapping

ECMA-334 first edition §9.5.7 defines a numeric line-indicator as decimal-digits, optionally followed by a nonempty quoted filename, with no stated Int32/PDB cap. Existing LineMapping.LogicalLine and MappedLocation.LogicalLine are Int32. Before the approved change, DirectiveEffects errored on #line 2147483648 and warned/ignored #line 16707566. The initial reproductions preceded the API change; current acceptance, exact metadata and checked compatibility behavior are covered by ExactLineMappingTests.

Approved design: retain Int32 physical offsets/physical line positions, add arbitrary-precision logical mapping metadata and an exact mapping query using BigInteger (BCL, no external dependency). Preserve raw directive spelling and original UTF-16 positions. Keep the current Int32 query as an explicitly checked conversion, with a Try form; never silently ignore a valid large directive or wrap its line value. Define one-based directive numbers separately from zero-based legacy display coordinates, including the grammar's zero spelling. Existing callers for normal-sized positive mappings retain their results. Tests must cover leading zeros, zero, Int32 edge, PDB edge and much larger values, reset/filename propagation and physical offsets.

Alternative: retain bounded Int32/PDB mapping and record exact logical mapping outside that range as unsupported coverage. Then the location-directive obligation remains open and CSharp1 cannot be declared complete for the pinned standard.

The user approved the recommended design on 2026-10-17. Implementation adds ExactLineMapping, ExactMappedLocation, ExactLineMappings and MapLocationExact on preprocessing results and parse documents. Exact logical coordinates are zero-based; LineNumber is the one-based view (zero remains zero). NumberSpelling preserves decimal spelling; DirectiveSpan refers to original UTF-16 offsets. Legacy LineMappings and MapLocation throw OverflowException for unrepresentable logical values; TryMapLocation returns false/null for overflow while invalid offsets still throw. Modern-profile PDB limits remain explicitly separate. Independent read-only review found no actionable correctness issue; a suggested CRLF/nonzero UTF-16 column case was added. This decision does not close other production review obligations.
