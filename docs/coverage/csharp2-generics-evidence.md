# CSharp2 generics vertical slice

Production .ngr extensions provide generic type arguments/qualified names, class/struct/interface/delegate/method parameters and constraints, generic method names, explicit-interface name suffixes, generic using targets, generic casts, definite generic-array casts and unbound typeof names. Existing ordinary declaration/name fields remain available; new optional fields expose additional typed syntax. Named capabilities now filter by an additive Introduced property, preserving the positional feature constructor. CSharp1 and CSharp1Safe omit the module. Explicit custom requirements remain required.

The public acceptance cycle failed ten cases before production changes and passed seventeen after the first implementation. Six alias/constraint-context cases then failed and passed after narrow typed seams and constraint ordering/owner checks. A definite generic-array cast failed before its dedicated cast-head alternative. The typed witness verifies parameter names/attributes, constraints, generic arguments, separators and authored spans; six oracle fixtures compare all generic argument lists, their delimiters/items/separators, type-parameter identifiers and constraint-clause spans.

Full code/typed verification before mapping metadata refresh: **842 normal + 3,251 oracle = 4,093 passed**, no failures/skips. The first full run caught an accidental module addition to CSharp1Safe and the expected stale source catalog; the composition was corrected and four unpopulated seams were added to the reviewed catalog. All CSharp1 view/source/policy gates pass after correction.

This is implemented partial syntax, not a completed normative review. The historical generics inventory entry remains unreviewed and CSharp2 remains partial. Generic unsafe pointer casts/member names and remaining cross-feature/historical lexical cases need continuation. The new mapping records supplying capability and policies without marking the source obligation verified. Existing semantic exclusions remain.
