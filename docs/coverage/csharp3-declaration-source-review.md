## Compilation units and namespaces: B8677–8690

CompilationUnits preserves extern aliases, then usings, then compilation-unit global attributes, then namespace/type members. Namespaces preserve their own extern/using/member order and optional trailing semicolon. Namespace names use qualified identifiers; generic/alias-qualified using names are supplied by NamesTypes/Generics/AliasQualification. Namespace versus type resolution, using alias identity, accessibility and import lookup require binding. CSharpCompilationUnitPolicy rejects assembly/module targets attached to namespace-level types after declarations or inside namespace bodies. Attribute target applicability on nested members remains semantic work.

## Generic type and member headers: B8692–8731

Declarations supplies class/struct/interface/enum/delegate categories, base lists and ordinary member spelling. Generics supplies attributed type parameters, nonempty type argument/parameter lists, qualified generic names and where clauses. DeclarationForms supplies partial type/method modifier recognition and accessor accessibility. The printed optional-suffix typo on namespace/type names is resolved by the controlling prose already recorded in the expression report. Main7068's ordinary interface method example resolves the missing optional marker on B8797 type-parameter-list; generic methods remain supported as well.

Type-base class/interface identity, type-parameter name binding, declaration spaces, constraint denotation/satisfaction/cycles and repeated constraint-name resolution remain excluded. Source-local constraint shape/order, class/struct position, constructor-last and struct/new incompatibility are checked. The inherited normalized contract retains the shared modifier vocabulary and its per-production finite-set over-approximation; general modifier compatibility/cardinality, static-class restrictions, accessor accessibility ordering/applicability, operator arity/types and enum underlying-type legality remain explicitly excluded. This does not claim distinct generated modifier-list node languages for each printed family. For example enum E:char remains an accepted syntax boundary with legality deferred, matching the reviewed earlier profiles.

Fields/constants retain comma declarators and expression/array initializers, with required constant values. Method/constructor/destructor bodies normalize block or semicolon spelling. Constructors retain optional base/this argument lists. Static constructors require empty parameters and no initializer; structs reject destructor and pre-CSharp10 explicit parameterless constructor/instance-field-initializer forms. Constructor-name matching, abstract/extern body applicability and definite assignment remain excluded semantic checks. Parameter attributes, ref/out modes, params-last lists and nonempty indexer parameters are preserved. Params dimensional/type legality remains in the inherited semantic boundary; indexer ref/out syntax is explicitly rejected.

## Properties, events, indexers and operators: B8732–8771

Property/indexer accessors preserve get/set ordering, attributes and semicolon/block bodies. Duplicate normalized accessor names are rejected. At most one accessor may declare accessibility; a single marked accessor requires the reviewed override exception, and explicit-interface accessors cannot declare accessibility. Interface accessors have semicolon bodies and no accessibility slot. Event accessor declarations require both add/remove blocks exactly once. Explicit interface name lookup and override/base matching are excluded.

CSharp3 automatic properties require both get and set with semicolon bodies for non-abstract/non-extern properties. Partial methods require void, a partial class/struct owner, final single partial modifier, permitted static/unsafe modifiers, no explicit interface name and no out parameters. Signature pairing, erased calls, accessibility/type identity and lowering remain excluded. ExtensionReceivers adds the optional this slot while preserving existing parameter fields. Source-local policy requires it on the first unmodified non-pointer parameter of a static method in a non-generic, non-nested static class. Pointer arrays remain valid receiver syntax; receiver type identity, extension lookup and inference are deferred.

Operator and conversion spellings use finite operator tokens, parameter lists, return/target types and method bodies. Unary/binary/conversion arity and operator compatibility retain the inherited semantic normalization rather than implying overload checking. Static constructors and finalizers share member/body owners; their independent source occurrences remain represented in the crosswalk.

## Structs, arrays, interfaces, enums and delegates: B8773–8813

Structs reuse the common member owners with the explicit restrictions above. Array-type/rank/initializer occurrences here remain distinct from the repeated type/expression occurrences: NamesTypes.ArrayRank/TypeReference, Expressions.ArrayInitializer/ArrayElement and Statements.VariableInitializer own them. Nested optional initializer lists, comma separators and trailing commas are preserved. Rank/dimension value agreement, element conversions and inferred types require semantic work.

Interface members admit method/property/event/indexer forms with required semicolons/accessor lists; ordinary and generic methods both follow the controlling example/prose correction noted above. Interfaces/delegates preserve generic constraints and preceding-version boundaries without introducing later variance, default interface bodies or optional parameter defaults. Enums preserve optional underlying spelling, optional/attributed comma-separated members, values and trailing comma. Underlying type legality, constant values, duplicate member identities and delegate compatibility remain excluded.

## Attributes: B8815–8833

Attributes supplies sections/targets, comma lists, alias/generic type-name spelling and argument lists. CSharp3 standard global targets are assembly/module; GlobalTargetsThird normalizes their identifier spellings using the frozen Unicode4 formatting table. Ordinary targets are field/event/method/param/property/return/type. CSharpAttributePolicy rejects unrecognized CSharp3 targets, including the earlier fourth-edition typevar spelling, while event/return require raw keyword spelling; identifier targets retain the declared normalization. Target applicability to the decorated symbol is deferred.

Historical attribute-argument-expression is expression, so assignment-shaped arguments remain syntax even where current compiler or constant/type validation rejects them. Positional arguments must precede named arguments, independently for each attribute; named member identity and constructor/constant/attribute type legality remain excluded. Alias-qualified and constructed attribute type-name syntax is recognized without claiming that generic attribute classes were legal in CSharp3. Attribute lists may end in a trailing comma; their argument lists may not.

## Finite execution evidence and limits

CSharp3DeclarationSourceTests covers compilation order, all type families, generic headers/constraints, parameters, members/accessors/operators, partial methods, extension receivers and attributes with accepted/malformed neighbors and original-coordinate bounds. CSharp3DeclarationTests separately retains edition boundaries and typed receiver fields/spans. CSharp3InheritedSourceTests/InheritedClosureTests execute retained older source cases in the actual third factory. The report crosswalk validates exact150 source identities, report hash and actual attributed-method references, with metadata mutations. Existence is not execution; recorded suite runs establish execution.

The finite groups do not establish per-alternative closure, arbitrary nesting/input coverage, compiler equivalence, binding or runtime semantics. Remaining explicit witness obligations and a separate fail-closed source/factory/policy contract precede any CSharp3 completeness promotion.
