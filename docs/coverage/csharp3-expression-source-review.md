## Names, types and variables: B8506–8534

NamesTypes supplies qualified names, predefined types, array ranks, TypeBase and TypeReference. Generics supplies type arguments and generic segments; AliasQualification supplies alias-qualified type prefixes; NullableValues supplies nullable spelling. The namespace-or-type-name summary's `type-argument-listop` typo is resolved by main1789–1793, which explicitly enumerates the optional generic cases on qualified segments. This is a transcription normalization supported by controlling prose. Numeric/enum/class/interface/delegate and named non-nullable distinctions require binding and collapse to common syntax owners. Namespace identity, type-parameter scope, named nullable underlying identity and unmanaged identity are excluded semantic checks. Explicit built-in reference nullable syntax, repeated nullable marks, nullable array/pointer suffix ordering, empty type arguments and sized array ranks remain syntax restrictions. `void` is a return/typeof/pointer special form, not an ordinary field type.

B8534 variable-reference normalizes expression syntax. Writable storage, ref/out suitability and definite assignment require binding. That normalization does not remove delimiter or argument-list restrictions.

## Primary expressions and creation: B8536–8572

Expressions owns arguments/ref/out modes, list separators, primary alternatives, array creation, checked/unchecked and ordinary typeof. DefaultValues and AnonymousMethods supply their additive forms. Generic expression arguments are retained only by the main3384–3386 follower rule: `( ) ] } : ; , . ? == !=`; `??` is not the single question token. Type arguments in type-name positions do not use this expression ambiguity rule. The extra closing-brace follower is supplied only by GenericFollowersThird. Approved source corrections preserve generic suffixes in base access, alias-qualified member access and pointer-member access, precisely as recorded in the separate approved decision; no wider correction authority is inferred.

AliasNameExpression is an internal prefix helper, not a freestanding primary expression. Existing syntax policy requires its ordinary/generic member owner. Casts of bare alias-qualified types are definite type grammar. `typeof` routes ordinary names through type syntax; an unbound name requires at least one generic dimension and cannot mix bound arguments with unbound dimensions or acquire array ranks. Object and delegate creation share the same spelling owner because resolving the created type is binding. Parentheses and argument lists remain required where specified.

ObjectInitializers distinguishes member and collection forms, optional constructor arguments, nested initializer values, trailing commas and nonempty braced expression lists. Scalar collection elements are non-assignment expressions; a parenthesized assignment is a primary expression and a braced list admits assignments. AnonymousTypes admits named members and inferred simple-name/member-access forms, excluding calls, element access and other arbitrary expressions. Duplicate member identity, Add lookup, collection-interface requirements, constructor/delegate compatibility and inferred types are semantic exclusions.

Sized and initialized explicit arrays retain element/rank/initializer lists; ImplicitArrays uses a rank specifier plus required initializer. Direct array-creation element access requires parentheses, while ordinary member access remains available. Rank/dimension value agreement and best-common-type inference are excluded semantic work. Empty/malformed ranks, sized trailing ranks, missing required initializers and mixed initializer categories remain syntax obligations.

## Unary, operators and assignments: B8573–8588, B8617–8622

Expressions uses Pratt precedence matching the source hierarchy, with null coalescing between conditional-or and conditional and right association for coalescing, conditional and assignment. Each conditional arm is a full expression. Assignment targets must have the unary syntactic category; writability is separately excluded. A type-operator operand is parsed as a type and cannot leak a primary suffix or tighter arithmetic/shift operator onto its result without parentheses. The approved type-operand wrapper preserves nullable versus conditional choice. Historical nullable `is` syntax is retained independently of current compiler restrictions.

Main3823–3827 controls cast ambiguity using correct token grammar without binding: definite type grammar starts a cast regardless of its next operand token; a name that is also expression grammar requires a qualifying follower. `(T)-x` is subtraction while `(A::T)-x` and `(int)-x` are casts. Unary-only operand categories and whole-input consumption remain checked. The printed en dash in additive-expression is normalized to ASCII minus, as identified by the lexical operator token and ordinary subtraction examples; U+2013 does not become an operator.

Constant-expression and boolean-expression normalize expression syntax; constness, conversions, operator overloads, result types and evaluation are excluded. Variable-reference, delegate creation and named type subcategories therefore do not claim semantic compilation.

## Anonymous functions and queries: B8589–8616

AnonymousMethods supplies optional explicitly typed delegate signatures and blocks. Lambdas supplies empty/single/implicit/explicit signatures, ref/out modes and expression/block bodies; parameter lists cannot mix implicit and explicit forms or add params/attributes. Low-precedence lambdas and queries are non-assignment expressions, not unparenthesized unary/binary operands. Parentheses restore primary syntax. Typed parameter names/modes/body ranges and nested lambda ownership have selected-factory witnesses. Delegate compatibility, capture analysis and expression-tree conversion remain excluded.

Queries supplies typed/untyped bindings, additional from/let/where/join/join-into/orderby clauses, order directions, select/group result and recursive into continuation. Main4315–4319 controls clause order and treats the thirteen raw query words as keywords anywhere inside a query expression. Verbatim/escaped identifier spellings retain the separately declared lexical behavior. Missing final results, misplaced clauses and raw reserved member/simple names are rejected. Range variable scope, LINQ pattern lookup, query translation, overload resolution and inference remain excluded; source inspection of translation prose is not a lowering implementation claim.
