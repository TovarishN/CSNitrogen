# CSharp7 source contract and Unicode continuity

All four CSharp7 profiles continue the frozen Unicode 4.0 scalar contract approved for CSharp6. This covers identifiers, trivia, preprocessing symbols, and the assembly and module target grammar. For example, all four profiles accept U+10400 in identifiers and reject U+0860. A supplementary identifier character immediately after a directive name stays part of that name, so it cannot act as a separated argument. CSharp8 uses the current BMP selection.

The published ECMA-334 seventh edition describes C# 7.3. The working annex has 489 rules and 1,221 alternatives. The comparison uses rule names and hashes of bodies after comment and whitespace normalization. It found 388 matching bodies, 46 changed bodies, 55 added names, and two removed names. The working annex and PDF annex agree for all 489 rules after normalization. Source inspection accounts for the 26 working-text blocks and 9 PDF spans unmatched by the prose search, including the CSharp7.3 `stackalloc` placement restriction. All four seventh profiles remain partial. The [release boundary observations](csharp7-release-boundary-evidence.md) record representative cases across 6.0 through 8.0. The numeric grammar selects binary literals and separators between digits starting at 7.0, with a separate extension for separators after a hexadecimal or binary prefix starting at 7.2. These spellings have their own token-valued expression nodes. The original literal expression and fragment keep their existing contract. [Tree decision](../superpowers/specs/2026-11-26-csharp7-numeric-syntax-decision.md) · [Numeric witnesses](../../tests/CSNitrogen.Tests/Syntax/CSharp7NumericLiteralTests.cs)

The C# 7.1 composition adds a token-valued node for untyped `default`. The typed `default(T)` form and the switch `default:` label retain their existing trees. The grammar leaves target typing and conversion to semantic analysis. [Default literal witnesses](../../tests/CSNitrogen.Tests/Syntax/CSharp71DefaultLiteralTests.cs)

The C# 7.0 throw-expression module uses the null-coalescing operand precedence. The host policy permits a throw expression as a direct conditional arm, the right operand of `??`, or an expression body. Exception conversion remains semantic. [Throw expression witnesses](../../tests/CSNitrogen.Tests/Syntax/CSharp7ThrowExpressionTests.cs)

The C# 7.0 event extension permits arrow bodies on `add` and `remove` and supports mixing them with blocks. Each event must declare exactly one of each accessor. Block-only declarations use the original typed tree. This is a reviewed departure from the seventh edition's block-only event grammar. [Approved event source contract](../superpowers/specs/2026-11-27-csharp7-event-accessor-source-decision.md) · [Event witnesses](../../tests/CSNitrogen.Tests/Syntax/CSharp7EventExpressionBodyTests.cs)

The C# 7.2 accessor module accepts both `private protected` and `protected private`. For an ordinary member or nested type, the source policy recognizes the pair within one modifier list and reports its later token before 7.2. Accessibility binding and general modifier-set validity remain outside this check. [Approved release boundary](../superpowers/specs/2026-11-27-csharp72-private-protected-source-decision.md) · [Parser witnesses](../../tests/CSNitrogen.Tests/Syntax/CSharp72PrivateProtectedTests.cs)
